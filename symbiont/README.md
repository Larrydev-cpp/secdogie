# symbiont: browser-side symbiotic runtime

Chinese: [README.zh.md](README.zh.md)

SecDogie's runtime in the browser: **dual Socratic gates** (Gate 1 semantic alignment +
Gate 2 cryptographic release), **attention-aware interruption scheduling**, and **topology
mapping** built on the Rust-WASM state graph ([`../graph/`](../graph/)). TypeScript with zero
runtime dependencies (WebCrypto for Ed25519 and SHA-256); Node 22 runs the `.ts` sources
directly, and the browser uses the `tsc` output.

**Byte-for-byte compatible** with the existing Python components: canonical JSON,
`secdogie/action-authorization/v1` tokens, `secdogie/dialogue/v1` envelopes, and the review
rules of `socratic.py`, locked by the golden vectors in
[`fixtures/vectors/`](../fixtures/vectors/) (generated by Python; Rust and TypeScript must
match).

## Three subsystems

| Subsystem | Modules | What it does |
| --- | --- | --- |
| A State graph and topology | `graph/wasm.ts` · `graph/topology.ts` · `sandbox/*` | Bounded fetching of public pages in a Worker → the WASM lexical route adapter emits **candidate states** → append-only deltas signed with the agent key → the WASM engine verifies the signature itself and stores them; have/want anti-entropy |
| B Attention scheduling | `attention/*` | Computes an `InterruptionBudget` (flow / engaged / gap / away / suppressed) from focus signals; the proposal queue is held during flow, surfaces during gaps, and is masked in sensitive contexts |
| C Dual Socratic gates | `gate1/*` · `gate2/*` · `gates/pipeline.ts` | Gate 1 asks one question at a time and produces no plan until aligned; after alignment, WASM precomputes the action deterministically; high-risk actions are released by the operator's Ed25519 signature through an inline prompt |

View layer: `stream/*`. A persistent "stream of consciousness" (swarm and topology state at
the top, never a blank page), narration folded by intent (never a step-by-step list of
mechanical operations), and **inline prompts** for Gate 1 / Gate 2 (never modal dialogs).

## How the hard constraints are enforced

- **No modal dialogs, no focus stealing, no injected markup.** `tests/purity.test.ts` scans
  `src/` and fails on `.focus(`, `showModal`, `role="dialog"`, `alert/confirm/prompt`,
  `innerHTML`, `eval`, `credentials: 'include'`, `redirect: 'follow'`, `localStorage` and the
  like.
- **Gate 2 is inline but not careless.** The prompt lists all six fields the signature
  commits to; "Approve" is ignored for 0.8 s after the prompt appears (against misclicks on a
  prompt that just popped up); in sensitive contexts the content is masked and cannot be
  approved; it is re-reviewed before signing. In the browser, the operator key unlocks only
  within a **genuine user click** (`navigator.userActivation`), so scripts on the page
  (including the agent itself) cannot obtain it; the signed token is self-verified locally
  before it is sent.
- **No implicit "yes".** An expired Gate 1 question = no; an expired Gate 2 challenge = the
  node refuses; the queue has no urgent pre-emption.
- **Two keys.** The agent's DID signs graph deltas and issues challenges; the operator's DID
  signs releases. The issuer releases only after `verifyAuthorization` checks the action hash,
  subject, validity window and trusted operator.
- **Candidate states only; no invented transitions.** Gate 1 can choose only among states
  already in the graph; when a state is missing, it asks rather than guesses. `plan_action`
  refuses states that are not in the graph.
- **Fetch boundary** (`sandbox/policy.ts`): https only, an exact origin allowlist (empty =
  fetch nothing), `credentials: 'omit'`, `referrerPolicy: 'no-referrer'`, bounded body size
  and time, `redirect: 'manual'` (reported only; the target becomes a candidate only if
  allowlisted, and is not followed). When the remote side does not allow cross-origin reads
  (CORS), the failure is reported as such, **never bypassed through a proxy**. The policy is
  fixed at Worker initialization and cannot be loosened afterwards.

### Limits of the focus signals (deliberate)

The requirements' "system-wide typing CPM" and "OS window context" are not available to a
browser; obtaining them would require a global keyboard hook, which is one step away from a
keylogger and is on the prohibited list. Therefore:

- `BrowserFocusProvider` observes only **this application's own document**: visibility,
  focus, and key / click **counts** (the listeners do not receive the event object and cannot
  read which key was pressed);
- system-side signals can come only from **authorized** sources (for example, the coarse
  application category from the node's accessibility layer, or a system idle-time API),
  delivered as aggregated samples through `ManualFocusProvider`. That source is not yet
  implemented.

## Cross-language canonicalization (Python float compatibility)

Signatures cover the bytes of Python's
`json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=False)`. JavaScript's
built-in JSON differs in four places, and `core/canon.ts` handles each:

| Case | Python | JS default | Here |
| --- | --- | --- | --- |
| Integral floats | `1759740120.0` | `1759740120` | Floats must be marked explicitly with `pyFloat()`; a bare `number` means an integer only |
| Exponents | `1e+16`, `1e-05` | `10000000000000000`, `0.00001` | Follows `repr`: exponent notation when `decpt <= -4 or > 16`, signed, at least two digits |
| Key order | By code point | By UTF-16 code unit | `compareCodePoints` |
| Large integers | Exact | Precision lost beyond 2^53 | `bigint` (the dialogue header's `timestamp_ns` is about 1.76e18) |
| `NaN`, duplicate keys, lone surrogates | Emitted / last one wins / error only at encoding | — | All rejected |

`parseLossless` distinguishes int from float with `json.loads`'s lexical rules, so
re-encoding a Python-signed object yields exactly the signed bytes. Graph deltas **contain no
floats**, so content addresses are unaffected by float rules.

## Running

```sh
npm ci
npm run build:wasm     # cargo-builds ../graph for wasm32 and copies it into wasm/
npm run typecheck
npm test               # node --test, including byte-for-byte comparison with the Python golden vectors and the four-stage journey
npm run build          # tsc -> dist/
python3 -m http.server 8080   # open http://localhost:8080/ for the offline demo
```

`tests/journey.test.ts` runs the real WASM engine through **FlowState (queued) →
AttentionGap → Gate 1 Socratic clarification → Gate 2 inline signature**, and covers question
expiry, deletion of the topology on rebuttal, masking in sensitive contexts, and signature
expiry.

## Not yet done

- A real transport bridge to the Python nodes (W3): the packet shapes are compatible, but the
  two sides currently connect in-page over loopback.
- The operator key lives only in memory (IndexedDB persistence and a browser DID belong to
  W1); a browser operator DID must first be registered in the node's operators.
- An inline confirmation prompt for memory candidates (`MemoryCandidatePacket`).
- Real system windows (requires a desktop shell); today the sandbox = a dedicated Worker + a
  non-modal in-page sidebar.
- A system-side focus-signal source (see above).
